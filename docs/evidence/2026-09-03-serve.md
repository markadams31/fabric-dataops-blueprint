# Step 7 — serve: Direct Lake model + PBIR report, and the executeQueries wall

**Date** 2026-09-03 · **Runs** build 33701573765/33701984329/33702396093/33703583540 → final green run follows this commit

## What was proven

- **Hand-authored TMDL and PBIR deploy.** `sm_sales` (Direct Lake on SQL: entity
  partitions over the `gold` schema, two measures) and `rpt_sales` (PBIR with a
  card visual, `byPath` model reference) publish via fabric-cicd with no Desktop
  involvement.
- **The hardest rebind in Fabric works.** The model's `DatabaseQuery` expression
  ships with placeholders; `parameter.yml` dynamic variables
  (`$items.Warehouse.wh_analytics.$sqlendpoint` / `.$id`) rewrite them per
  environment. Verified in the deployed definition. Two integration facts:
  `deploy_with_config` does **not** auto-discover `parameter.yml` (set
  `core.parameter`), and current syntax wants `$`-prefixed attributes.
- **Direct Lake serves without explicit refresh** — a query returned
  orders=300/customers=100 while *enhanced refresh* failed ("cannot access the
  source Delta table") right after warehouse writes. Reframe-on-query (E21) is the
  dependable path; the deploy relies on it.

## The wall: executeQueries is closed to service principals here (E14, confirmed deep)

The 2026 docs say service principals can call `executeQueries` given Build
permission and tenant switches. Empirically, in this tenant, **every** documented
and undocumented condition was satisfied and both SPN types still get
`PowerBINotAuthorizedException`:

| Checked | State |
|---|---|
| `ServicePrincipalAccessPermissionAPIs` (Fabric public APIs) | Enabled, scoped to the automation group (both principals members) |
| `DatasetExecuteQueries` | Enabled org-wide; ALSO tested explicitly scoped to the automation group via the admin Update API |
| Dataset permission | `ReadWriteReshareExplore` (workspace Member) |
| The classic "Allow service principals to use Power BI APIs" switch | Does not exist in this tenant — confirmed via the admin tenant-settings API (175 settings enumerated) |
| Managed identity vs app registration + client secret | **Both 401** — controlled experiment with a temporary Member role for the classic SPN |
| A user (same workspace, same query) | Works |
